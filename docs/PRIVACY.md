# 隐私与数据说明

## 给使用者

项目没有公共服务器或共享 API Key。凭据由你填写在 Loon 参数或自己的服务器环境文件中，不包含在仓库的公开脚本里。

使用 Gemini 翻译时，字幕文本会发送给 Google；通过 SubDL 搜索时会发送影片信息。启用外部字幕模式后，Loon 会向你填写的服务器提交影片元数据和 Apple 参考播放 URL，服务器会保存参考信息、下载 CC 媒体采样，并缓存处理后的字幕。

Loon 参数不是加密保险箱。配置导出、截图、抓包和日志可能包含 API Key、网关访问令牌或 Apple 临时签名 URL。提交 Issue 时，优先提供错误现象、版本和已遮盖敏感值的必要日志，不要直接附上完整配置或原始抓包。使用非自建服务器时，应了解维护者能看到和保存哪些数据。

API Key 或访问令牌泄漏后，应在相应服务中吊销或更换；仅删除公开截图或文件不能保证撤回已经被复制的凭据。

## 给贡献者：提交与发布检查

下面是维护代码时的检查清单，不是普通安装用户需要执行的步骤。

- `GeminiAPIKey`、`SUBDL_API_KEY`、`GEMINI_API_KEY` 必须由使用者填写，不提交到 Git。
- `GatewayURL` 留空，部署示例使用 `subtitles.example.com`，没有私人 IP、域名、云项目或 SSH 用户。
- `ACCESS_TOKEN` 示例是假占位符，部署时必须更换随机令牌。
- 不提交 HAR、Loon 备份、缓存字幕、日志、证书、环境文件、登录令牌或完整历史工作目录。
- 编译 JS 也可能泄密，因此每次修改后必须重建，并扫描所有公开文件；只检查源码不够。
- `npm run privacy` 是启发式检查，不等于秘密检测的完备证明；发布者还须核对文件列表、差异和历史。
- 不要在 Issue 中粘贴完整播放 URL、网关 URL、API 错误原文或未清理抓包。
- Loon INFO/DEBUG 日志、反向代理日志及 Apple 临时签名 URL 都应视为敏感资料。
- 分享插件参数截图前遮挡凭据，使用独立且限制额度的 API Key。

如果秘密曾进入公开提交，删文件或重写历史不能保证撤回所有副本：应先吊销并更换对应凭据。不要把实际凭据作为“测试样例”提交。
